# VisionAssist Testing Strategy & Quality Assurance Plan

This document provides a comprehensive evaluation of the testing infrastructure in **VisionAssist Smart Glasses**, identifies critical coverage gaps across all layers, and establishes mocking and validation strategies for hardware, AI/ML models, and assistive UI components.

## 1. Current Test Setup & Existing Test Analysis

### 1.1 Existing Test Assessment
The project currently has a single test file located at [test/widget_test.dart](file:///c:/Users/admin/OneDrive/Desktop/Glasses%20for%20blind%20by%20anity/test/widget_test.dart):

```dart
void main() {
  testWidgets('SmartGlassesApp smoke test', (WidgetTester tester) async {
    // Build our app and trigger a frame.
    await tester.pumpWidget(const SmartGlassesApp());

    // Verify that our counter starts at 0.
    expect(find.text('0'), findsOneWidget);
    expect(find.text('1'), findsNothing);

    // Tap the '+' icon and trigger a frame.
    await tester.tap(find.byIcon(Icons.add));
    await tester.pump();

    // Verify that our counter has incremented.
    expect(find.text('0'), findsNothing);
    expect(find.text('1'), findsOneWidget);
  });
}
```

### 1.2 Autopsy & Failure Analysis
This test is the boilerplate counter test generated by `flutter create` and is **completely broken**:
1. **Missing ProviderScope**: [SmartGlassesApp](file:///c:/Users/admin/OneDrive/Desktop/Glasses%20for%20blind%20by%20anity/lib/app.dart#L10) instantiates [HomeScreen](file:///c:/Users/admin/OneDrive/Desktop/Glasses%20for%20blind%20by%20anity/lib/ui/home_screen.dart#L20), which is a `ConsumerStatefulWidget` interacting with Riverpod providers. In [main.dart](file:///c:/Users/admin/OneDrive/Desktop/Glasses%20for%20blind%20by%20anity/lib/main.dart#L10), the app is wrapped in `ProviderScope`, but `widget_test.dart` pumps `const SmartGlassesApp()` without `ProviderScope`. This causes Flutter to throw an immediate unhandled exception:
   ```
   Bad state: No ProviderScope found when building HomeScreen
   ```
2. **Non-Existent UI Elements**: The test asserts the presence of `'0'`, `'1'`, and `Icons.add`. None of these exist anywhere in the VisionAssist application. Running `flutter test` fails immediately.
3. **Hardware & Plugin Crashes in Headless Testing**: If `HomeScreen` were to mount, its `initState` triggers post-frame callbacks calling:
   - `cameraStateProvider.notifier.initialize()` (calls native camera APIs)
   - `ttsStateProvider.notifier.initialize()` (calls native TTS engine)
   - `Permission.camera.request()` (calls native permission handler)
   - `voiceAssistantStateProvider.notifier.startContinuousListening()` (calls native speech recognition)
   Without mocks or platform channel interceptors, headless test runners crash immediately on missing platform plugins.

### 1.3 Dependency Status
In [pubspec.yaml](file:///c:/Users/admin/OneDrive/Desktop/Glasses%20for%20blind%20by%20anity/pubspec.yaml#L32-L36):
```yaml
dev_dependencies:
  flutter_test:
    sdk: flutter
  flutter_lints: ^5.0.0
```
- **Current Coverage**: **0%** real application coverage.
- **Missing Tooling**: No mocking framework (`mocktail` or `mockito`) is declared in `dev_dependencies`.

## 3. Hardware Dependency Mocking Strategy

The app interacts with 6 distinct hardware peripherals and native subsystems. To test reliably in automated CI/CD without physical devices connected, each hardware interface requires a standardized mocking strategy.

### 3.1 Camera & UVC Stream Mocking
- **Native Smartphone Camera (`camera` package)**:
  - Do not mock the underlying platform channel directly.
  - Implement a mock `CameraController` or mock `NativeCameraSource` implementing the [CameraSource](file:///c:/Users/admin/OneDrive/Desktop/Glasses%20for%20blind%20by%20anity/lib/services/camera_service.dart#L8) interface.
  - Stream synthetic `CameraImage` objects into `frameStreamController`.
- **External USB-C IMX378 Smart Glasses (`flutter_ffi_uvc`)**:
  - Mock top-level functions or wrap `uvcCamera` calls in a testable wrapper class.
  - Simulate USB device attachment via `listUsbDevices() -> [UsbDeviceInfo(deviceId: 1001)]`.
  - Stub `extractFrame()` to return pre-recorded JPEG fixture byte arrays.

### 3.2 Text-to-Speech (`flutter_tts`) Mocking
- In [TTSService](file:///c:/Users/admin/OneDrive/Desktop/Glasses%20for%20blind%20by%20anity/lib/services/tts_service.dart#L21), wrap `FlutterTts` or substitute with a mock implementing the same interface.
- Simulate callback triggers:
  ```dart
  when(() => mockFlutterTts.speak(any())).thenAnswer((invocation) async {
    // Immediately trigger start handler, then complete after synthetic delay
    startHandler?.call();
    Future.delayed(const Duration(milliseconds: 50), () => completionHandler?.call());
    return 1;
  });
  ```
- **Watchdog Test**: Verify that if `completionHandler` is never called, the `_speechWatchdogTimer` automatically resets `isSpeaking` to `false`.

### 3.3 Speech-to-Text (`speech_to_text`) Mocking
- Mock `stt.SpeechToText`.
- Simulate user speech recognition events:
  - Add test strings to `onResult` callback: e.g. `"hey echo open currency"`, `"where am i"`, `"navigate to central park"`.
  - Simulate status callbacks (`listening`, `notListening`, `done`) to test continuous loop re-arming.

### 3.4 Geolocation & Compass Mocking
- Mock [LocationService](file:///c:/Users/admin/OneDrive/Desktop/Glasses%20for%20blind%20by%20anity/lib/services/location_service.dart#L7):
  - Return fixed `Position` instances: `Position(latitude: 28.6139, longitude: 77.2090, ...)` (e.g. New Delhi).
  - Inject custom `StreamController<Position>` to simulate walking down a street and verify turn-by-turn prompts.

## 4. Machine Learning & Cloud AI Testing Strategy

### 4.1 Google Gemini AI (Cloud Multimodal & Intent)
- **Service**: [GeminiAssistantService](file:///c:/Users/admin/OneDrive/Desktop/Glasses%20for%20blind%20by%20anity/lib/services/gemini_assistant_service.dart).
- **Mock Target**: Mock `GenerativeModel` from `package:google_generative_ai`.
- **Test Scenarios**:
  1. **Valid JSON Intent Response**: Return `{"action": "currency", "response": "Opening Currency"}` -> Assert `VoiceCommandType.openCurrency`.
  2. **Navigation with Argument**: Return `{"action": "navigation", "destination": "Apollo Hospital", "response": "Navigating to Apollo Hospital"}` -> Assert argument is extracted.
  3. **Multimodal Scene Inquiry**: User asks `"What am I looking at?"` -> Verify image bytes are passed in `Content.multi([TextPart, DataPart])`.
  4. **Network Timeout / Failure Fallback**: When `_textModel.generateContent` throws `ClientException` or times out, verify that `_offlineSemanticClassify()` seamlessly executes and returns the correct intent without throwing.

### 4.2 Google ML Kit Text Recognition & Image Labeling
- **Services**: [OcrService](file:///c:/Users/admin/OneDrive/Desktop/Glasses%20for%20blind%20by%20anity/lib/services/ocr_service.dart), [ObjectDetectionService](file:///c:/Users/admin/OneDrive/Desktop/Glasses%20for%20blind%20by%20anity/lib/services/object_detection_service.dart), [CurrencyService](file:///c:/Users/admin/OneDrive/Desktop/Glasses%20for%20blind%20by%20anity/lib/services/currency_service.dart).
- **Mock Target**: Mock `TextRecognizer` and `ImageLabeler`.
- **Test Scenarios**:
  1. **Banned Labels Suppression**: Feed `ImageLabel` with label `"pattern"` (confidence 0.9) alongside `"laptop"` (confidence 0.6). Assert result is `"Laptop"`, strictly filtering out `"pattern"`.
  2. **Currency OCR**: Feed `RecognizedText` containing `"RESERVE BANK OF INDIA 500 RUPEES"`. Assert `CurrencyResult.denomination == '500'`.
  3. **OCR Top-to-Bottom Sorting**: Feed blocks out of order. Assert `fullText` arranges blocks sorted by `boundingBox.top`.

### 4.3 On-Device TFLite Models
- **Service**: [TFLiteService](file:///c:/Users/admin/OneDrive/Desktop/Glasses%20for%20blind%20by%20anity/lib/services/tflite_service.dart).
- Native C++ TFLite binaries cannot run in headless desktop `flutter test` without platform wrappers.
- Strategy: Abstract `Interpreter` behind an interface or test pre-processing and post-processing mathematical pipelines independently of the native inference runner.

## 5. Recommended Testing Architecture & Mock Framework

### 5.1 Recommended Framework: `mocktail`
We recommend adding **`mocktail: ^1.0.4`** to `dev_dependencies` in [pubspec.yaml](file:///c:/Users/admin/OneDrive/Desktop/Glasses%20for%20blind%20by%20anity/pubspec.yaml):
- **Why `mocktail` over `mockito`?**
  - **Zero code generation**: No need to maintain `@GenerateMocks` annotations or run `dart run build_runner build`.
  - **Full Dart 3 Null Safety**: Direct type inference with fallback values via `registerFallbackValue()`.
  - Clean, idiomatic syntax.

### 6.1 Unit Test Blueprint: `DetectionResult` Spatial Logic
File: `test/unit/models/detection_result_test.dart`

```dart
import 'package:flutter_test/flutter_test.dart';
import 'package:smart_glasses/models/detection_result.dart';

void main() {
  group('DetectionResult Spatial Tests', () {
    const double imageWidth = 300.0;

    test('calculates left position when center is in left third', () {
      final result = DetectionResult.fromTFLiteOutput(
        'Bottle',
        0.9,
        [20.0, 50.0, 40.0, 80.0], // Center X = 20 + 20 = 40 (< 100)
        imageWidth,
      );

      expect(result.relativePosition, 'left');
      expect(result.toSpeechText(), 'Bottle to the left');
    });

    test('calculates ahead position when center is in middle third', () {
      final result = DetectionResult.fromTFLiteOutput(
        'Chair',
        0.85,
        [130.0, 50.0, 40.0, 80.0], // Center X = 130 + 20 = 150 (between 100 and 200)
        imageWidth,
      );

      expect(result.relativePosition, 'ahead');
      expect(result.toSpeechText(), 'Chair ahead');
    });

    test('calculates right position when center is in right third', () {
      final result = DetectionResult.fromTFLiteOutput(
        'Person',
        0.95,
        [220.0, 50.0, 40.0, 80.0], // Center X = 220 + 20 = 240 (> 200)
        imageWidth,
      );

      expect(result.relativePosition, 'right');
      expect(result.toSpeechText(), 'Person to the right');
    });
  });
}
```

### 6.2 Widget Test Blueprint: `AccessibleButton` Accessibility Standards
File: `test/widget/accessible_button_test.dart`

```dart
import 'package:flutter/material.dart';
import 'package:flutter_test/flutter_test.dart';
import 'package:smart_glasses/ui/widgets/accessible_button.dart';

void main() {
  testWidgets('AccessibleButton meets accessibility standards', (tester) async {
    bool wasPressed = false;

    await tester.pumpWidget(
      MaterialApp(
        home: Scaffold(
          body: AccessibleButton(
            label: 'Read Text',
            icon: Icons.menu_book,
            semanticLabel: 'Read Text Mode Button',
            onPressed: () => wasPressed = true,
          ),
        ),
      ),
    );

    // 1. Verify Minimum Touch Target Constraint (>= 80dp)
    final renderBox = tester.renderObject<RenderBox>(find.byType(AccessibleButton));
    expect(renderBox.size.height, greaterThanOrEqualTo(80.0));

    // 2. Verify Semantics Node
    final semantics = tester.getSemantics(find.byType(AccessibleButton));
    expect(semantics.label, contains('Read Text Mode Button'));
    expect(semantics.hasFlag(SemanticsFlag.isButton), isTrue);

    // 3. Verify Tap Triggering
    await tester.tap(find.byType(AccessibleButton));
    await tester.pump();
    expect(wasPressed, isTrue);
  });
}
```

### 6.3 Provider Test Blueprint: `TTSStateNotifier` State Transitions
File: `test/unit/providers/tts_providers_test.dart`

```dart
import 'package:flutter_test/flutter_test.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';
import 'package:mocktail/mocktail.dart';
import 'package:smart_glasses/providers/tts_providers.dart';
import 'package:smart_glasses/services/tts_service.dart';

class MockTTSService extends Mock implements TTSService {}

void main() {
  late MockTTSService mockTTSService;
  late ProviderContainer container;

  setUp(() {
    mockTTSService = MockTTSService();
    when(() => mockTTSService.speakingStream).thenAnswer((_) => Stream.value(false));
    when(() => mockTTSService.initialize()).thenAnswer((_) async {});
    when(() => mockTTSService.setLanguage(any())).thenAnswer((_) async {});
    when(() => mockTTSService.speak(any(), interrupt: any(named: 'interrupt'))).thenAnswer((_) async {});

    container = ProviderContainer(
      overrides: [
        ttsServiceProvider.overrideWithValue(mockTTSService),
      ],
    );
  });

  tearDown(() => container.dispose());

  test('speak updates TTSState with current text and calls TTSService', () async {
    final notifier = container.read(ttsStateProvider.notifier);

    await notifier.speak('Obstacle ahead');

    final state = container.read(ttsStateProvider);
    expect(state.isSpeaking, isTrue);
    expect(state.currentText, 'Obstacle ahead');
    verify(() => mockTTSService.speak('Obstacle ahead', interrupt: false)).called(1);
  });
}
```

## 7. Test Execution & Automation Guide

### 7.1 Recommended CLI Commands
Run commands from the project root directory:

```bash
# 1. Run all unit and widget tests
flutter test

# 2. Run only fast unit tests (skip UI rendering)
flutter test test/unit/

# 3. Run a specific test suite
flutter test test/unit/models/detection_result_test.dart

# 4. Run tests and generate code coverage report
flutter test --coverage

# 5. Format and inspect coverage locally (requires lcov)
genhtml coverage/lcov.info -o coverage/html
```
